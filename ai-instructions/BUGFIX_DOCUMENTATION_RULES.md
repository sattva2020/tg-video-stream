# КРИТИЧНО: Правила размещения документации по багфиксам

## ⚠️ ОБЯЗАТЕЛЬНОЕ ПРАВИЛО

**ВСЕ документы об исправлении багов ДОЛЖНЫ сохраняться ТОЛЬКО в:**
```
docs/bugfixes/
```

## 📝 Формат имени файла

```
COMPONENT_BUG_DESCRIPTION.md
```

**Примеры:**
- ✅ `TELEGRAM_2FA_FIX.md` - исправление 2FA в Telegram авторизации
- ✅ `DATABASE_MIGRATION_ERROR.md` - проблема с миграциями БД
- ✅ `REDIS_CONNECTION_TIMEOUT.md` - таймауты подключения к Redis
- ❌ `fix.md` - слишком общее название
- ❌ `telegram_bug.md` - недостаточно описательное

## 📋 Обязательное содержание документа

Каждый документ о багфиксе ДОЛЖЕН включать:

### 1. Описание проблемы
```markdown
## 🔴 Проблема
[Четкое описание бага, как он проявляется]
```

### 2. Воспроизведение
```markdown
## 🔄 Шаги воспроизведения
1. Шаг 1
2. Шаг 2
3. Ожидаемое поведение vs Фактическое
```

### 3. Корневая причина
```markdown
## 🔍 Корневая причина
[Техническое объяснение, почему баг возник]
```

### 4. Решение
```markdown
## ✅ Решение
[Подробное описание исправления с примерами кода]
```

### 5. Изменённые файлы
```markdown
## 📁 Изменённые файлы
- [путь/к/файлу.py](../../путь/к/файлу.py) - описание изменений
```

### 6. Тестирование
```markdown
## 🧪 Тестирование
[Как протестировать исправление]
```

### 7. Статус деплоя
```markdown
## 🚀 Статус
- [x] Исправление реализовано
- [x] Задеплоено на VPS
- [x] Протестировано
```

## 🔗 Обновление ссылок

После создания документа в `docs/bugfixes/` ОБЯЗАТЕЛЬНО обновить:

1. **ai-instructions/README.md** - добавить ссылку в соответствующий раздел
2. **README.md** - если баг касается основного функционала
3. **ai-instructions/COMPONENT_TECHNICAL.md** - в раздел "Документация"

## ✅ Чеклист при создании документа багфикса

- [ ] Файл создан в `docs/bugfixes/`
- [ ] Имя файла соответствует формату `COMPONENT_BUG_DESCRIPTION.md`
- [ ] Включены все обязательные разделы
- [ ] Примеры кода с подсветкой синтаксиса
- [ ] Ссылки на изменённые файлы относительные (`../../`)
- [ ] Обновлены ссылки в ai-instructions/README.md
- [ ] Обновлён README.md (если необходимо)
- [ ] Указан статус деплоя
- [ ] Добавлена дата исправления

## 📚 Пример структуры

```
docs/
├── bugfixes/
│   ├── TELEGRAM_2FA_FIX.md
│   ├── TELEGRAM_AUTH_FIX_SUMMARY.md
│   ├── DATABASE_MIGRATION_ERROR.md
│   └── REDIS_CONNECTION_TIMEOUT.md
├── api/
├── architecture/
└── development/
```

## 🚫 Что НЕ размещать в docs/bugfixes/

- ❌ Общие технические документы → `docs/development/`
- ❌ API документация → `docs/api/`
- ❌ Архитектурные решения → `docs/architecture/`
- ❌ Спецификации фич → `specs/`
- ❌ Планы разработки → корень проекта или `specs/`

---

**ЗАПОМНИ:** Любой документ об исправлении бага = `docs/bugfixes/` + имя формата `COMPONENT_BUG_DESCRIPTION.md`
