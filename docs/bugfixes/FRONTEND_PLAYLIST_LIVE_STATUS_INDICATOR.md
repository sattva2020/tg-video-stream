# Багфикс: live-индикатор плейлистов не отображался после «Транслировать сейчас»

Дата: 2025-12-18  
Автор: Jarvis (GitHub Copilot)

## Контекст
В UI карточек плейлистов реализован индикатор «сейчас транслируется» (красная точка). После запуска трансляции через пункт меню «Транслировать сейчас» пользователь видел успешный toast («Трансляция запущена!»), но индикатор на карточке не появлялся.

## Симптомы
- Пункт меню «Транслировать сейчас» доступен и запускает трансляцию.
- Toast об успешном запуске появляется.
- На карточке плейлиста красная точка live-статуса не появляется.

## Причина
Live-статус вычислялся через `useScheduleSlots(channelId, startDate, endDate)`.

Когда `channelId` в `PlaylistManager` не выбран (страница/режим без привязки к конкретному каналу), хук `useScheduleSlots` не выполнял запрос, потому что имеет `enabled: !!channelId`.

В итоге массив слотов оставался пустым, а функция проверки активности всегда возвращала `false`.

## Решение
1. Добавлен хук `useScheduleSlotsForChannels(channelIds, startDate, endDate)`, который загружает слоты сразу по нескольким каналам (через `useQueries`).
2. В `PlaylistManager` логика выбора слотов стала следующей:
   - если `channelId` выбран — используем слоты только этого канала;
   - если `channelId` не выбран — агрегируем слоты всех каналов и определяем live-статус по ним.
3. Для UX добавлен верхний индикатор-счётчик: `В эфире: N` (количество уникальных плейлистов, у которых есть активный слот).

## Что изменилось
- Логика live-индикатора стала корректной в режиме без выбранного канала.
- Появился счётчик активных плейлистов в заголовке менеджера плейлистов.

## Проверка (ручная)
1. Открыть страницу с плейлистами без выбора конкретного канала.
2. Нажать «Транслировать сейчас» → выбрать канал.
3. Убедиться, что:
   - toast сообщает об успешном запуске;
   - на карточке соответствующего плейлиста появляется красная точка;
   - в заголовке отображается «В эфире: 1» (или больше, если запущены несколько).
