## Что такое A/B тестирование?

A/B тестирование — это метод маркетингового исследования, при котором аудитория разделяется на группы для сравнения эффективности различных вариантов контента, расписаний или конфигураций.

### Возможности системы

- ✅ **Создание тестов**: Сравнивайте от 2 до 10 вариантов одновременно
- ✅ **Автоматическое распределение**: Настройте процент трафика для каждого варианта
- ✅ **Статистический анализ**: Автоматический расчет значимости, доверительных интервалов и p-value
- ✅ **Рекомендации**: Система подсказывает победителя на основе данных
- ✅ **Разные метрики**: Отслеживайте показы, клики, конверсии, время просмотра и другие метрики
- ✅ **Визуализация**: Графики и таблицы с результатами в реальном времени

## Для чего использовать A/B тестирование?

### Сценарии использования

1. **Тестирование превью-изображений**
   - Сравните разные обложки для видео
   - Узнайте, какой стиль привлекает больше зрителей

2. **Оптимизация расписания**
   - Сравните утренние и вечерние стримы
   - Найдите лучшие дни недели для трансляций

3. **Тестирование плейлистов**
   - Сравните разные порядки треков
   - Проверьте разные жанры или настроения

4. **Конфигурации стрима**
   - Сравните разные битрейты
   - Протестируйте разные форматы видео

5. **Маркетинговые материалы**
   - Тест заголовков и описаний
   - Сравнение призывов к действию (CTA)

## Основные понятия

### Вариант (Variant)

Один из вариантов, которые вы сравниваете. Например:
- Вариант A: Текущее превью (контроль)
- Вариант B: Новое яркое превью
- Вариант C: Превью с текстом

### Распределение трафика (Traffic Allocation)

Процент аудитории, которая увидит конкретный вариант. Сумма всех вариантов должна быть 100%.

Пример:
- Вариант A: 34% (контрольная группа)
- Вариант B: 33%
- Вариант C: 33%

### Метрики (Metrics)

Показатели, по которым вы измеряете успех:

| Метрика | Описание | Когда использовать |
|---------|----------|-------------------|
| **Impressions** | Количество показов варианта | Для измерения охвата |
| **Clicks** | Количество кликов | Для тестирования CTR кнопок/баннеров |
| **Conversions** | Конверсии (целевые действия) | Основная метрика для большинства тестов |
| **Watch Time** | Время просмотра в секундах | Для оценки удержания |
| **Peak Listeners** | Пик слушателей | Для сравнения максимальной аудитории |
| **Avg View Duration** | Средняя длительность просмотра | Для качества контента |

### Конверсия (Conversion rate)

Отношение конверсий к показам:

```
Конверсия = (Conversions / Impressions) × 100%
```

Пример: Если 100 человек увидели вариант и 15 из них совершили целевое действие, конверсия = 15%.

### Статистическая значимость

Показатель того, что результаты теста не случайны. Обычно используется порог 95% (p-value < 0.05).

- ✅ **Значимый результат**: Можете доверять данным
- ⚠️ **Недостаточно данных**: Соберите еще данных

### Доверительный интервал (Confidence Interval)

Диапазон, в котором с вероятностью 95% находится истинное значение конверсии.

Пример:
- Конверсия варианта A: 15% (95% CI: 12-18%)
- Конверсия варианта B: 19% (95% CI: 16-22%)

Если интервалы не пересекаются → результат значимый!

## Рабочий процесс A/B тестирования

### Шаг 1: Планирование теста

Перед созданием теста ответьте на вопросы:

1. **Что мы тестируем?**
   - Превью, расписание, плейлист, конфигурацию?

2. **Какова гипотеза?**
   - "Яркие превью увеличат конверсию на 15%"
   - "Вечерние стримы привлекают больше зрителей"

3. **Какую метрику оптимизируем?**
   - Конверсии (подписки, клики)
   - Время просмотра
   - Количество зрителей

4. **Сколько вариантов?**
   - Минимум 2 (A/B)
   - Рекомендуется 2-3 для быстрых результатов
   - Больше 5 — требует много данных

### Шаг 2: Создание теста через мастер

1. Перейдите в **Админка** → **A/B тестирование**
2. Нажмите кнопку **"Создать тест"**
3. Заполните 4 шага мастера:

#### Шаг 1: Основная информация

- **Название**: "Тест превью-изображений"
- **Описание": "Сравниваем 3 варианта превья"
- **Гипотеза**: "Яркие превью увеличат конверсию на 15%"
- **Длительность**: 24-72 часа (зависит от трафика)

#### Шаг 2: Варианты

Добавьте минимум 2 варианта:

**Вариант A (Контроль):**
- Название: "Текущее превью"
- Распределение трафика: 34%
- Конфигурация: `thumbnail_url: ".../thumb_a.jpg"`

**Вариант B:**
- Название: "Яркое превью"
- Распределение трафика: 33%
- Конфигурация: `thumbnail_url: ".../thumb_b.jpg"`

**Вариант C:**
- Название: "Контрастное превью"
- Распределение трафика: 33%
- Конфигурация: `thumbnail_url: ".../thumb_c.jpg"`

> **Важно**: Сумма распределения должна быть 100%!

#### Шаг 3: Конфигурация

- **Длительность теста**: Выберите от 1 до 168 часов (7 дней)
- **Уровень доверия**: Оставьте 95% (рекомендуется)

#### Шаг 4: Проверка

Проверьте все данные и нажмите **"Создать тест"**.

### Шаг 3: Запуск теста

1. Найдите созданный тест в списке (статус: **Черновик**)
2. Нажмите кнопку **▶️ Запустить**
3. Статус изменится на **Запущен**
4. Система начнет распределять трафик между вариантами

### Шаг 4: Сбор данных

Пока тест запущен, система автоматически собирает метрики:

- **Показы (Impressions)**: Считаются автоматически при показе варианта
- **Конверсии (Conversions)**: Записывайте через API при целевом действии

Пример записи конверсии (backend):

```python
from src.services.ab_testing_service import ABTestingService

# Запись конверсии для варианта
await service.record_metric(
    metric_data=ABTestMetricCreate(
        variant_id=variant_uuid,
        metric_type="conversions",
        metric_value=1,
        metadata={"user_id": user.id}
    )
)
```

Пример записи конверсии (frontend):

```typescript
import { recordABTestMetric } from '@/api/ab_testing';

// Запись конверсии
await recordABTestMetric({
  variant_id: variantId,
  metric_type: 'conversions',
  metric_value: 1,
  metadata: { user_id: userId }
});
```

### Шаг 5: Мониторинг результатов

1. Откройте тест из списка
2. Перейдите на вкладку **"Результаты"**
3. Вы увидите:

**График конверсий:**
- Столбцы для каждого варианта
- Error bars (доверительные интервалы)
- Зеленая подсветка победителя

**Карточка победителя:**
- Название варианта-победителя
- Улучшение в процентах
- P-value

**Статистика:**
- Показы, конверсии, конверсия
- Доверительный интервал (lower/upper)
- Статистическая значимость

### Шаг 6: Остановка теста и выбор победителя

Тест можно остановить двумя способами:

#### Автоматическая остановка (рекомендуется)

1. Нажмите **⏹️ Остановить тест**
2. Система автоматически выберет победителя на основе:
   - Самой высокой конверсии
   - Статистической значимости (p < 0.05)
3. Статус изменится на **Остановлен**
4. Победитель будет отмечен 🏆

#### Ручная остановка

1. Нажмите **⏹️ Остановить тест**
2. Выберите **"Выбрать победителя вручную"**
3. Укажите ID варианта-победителя
4. Подтвердите выбор

### Шаг 7: Анализ и принятие решений

После остановки теста проанализируйте результаты:

1. **Проверьте статистическую значимость**
   - ✅ Значимый (p < 0.05): Доверяйте результатам
   - ⚠️ Незначимый: Соберите еще данных или повторите тест

2. **Сравните доверительные интервалы**
   - Если интервалы не пересекаются → разница реальна
   - Если пересекаются → нужно больше данных

3. **Оцените улучшение**
   - Вариант B лучше A на 16%: хороший результат
   - Улучшение < 5%: может быть незначимым для бизнеса

4. **Примите решение**
   - Внедрите победителя на 100% трафика
   - Сохраните результаты для будущих тестов
   - Поделитесь выводами с командой

## Лучшие практики

### 1. Правило одной переменной

Тестируйте только одну вещь за раз:

❌ **Плохо**: Тестирование нового превья + нового описания + новой кнопки
✅ **Хорошо**: Тестирование только нового превья

### 2. Контрольная группа

Всегда оставляйте текущую версию как контроль (baseline):

- Вариант A: Текущее превья (34%)
- Вариант B: Новое превья (33%)
- Вариант C: Другое новое (33%)

### 3. Достаточная длительность

Давайте тесту время для сбора данных:

| Трафик в день | Минимальная длительность |
|---------------|-------------------------|
| 100 посетителей | 7-14 дней |
| 1,000 посетителей | 3-5 дней |
| 10,000 посетителей | 1-2 дня |

> Не останавливайте тест слишком рано! Результаты могут быть случайными.

### 4. Статистическая значимость

Не принимайте решения без проверки значимости:

- ✅ p-value < 0.05 → доверяйте результатам
- ⚠️ p-value > 0.05 → соберите еще данных
- ❌ Не принимайте решения на основе малых выборок

### 5. Равномерное распределение

Распределяйте трафик равномерно:

✅ **Хорошо**: 34% / 33% / 33%
⚠️ **Приемлемо**: 50% / 50%
❌ **Плохо**: 90% / 5% / 5% (тест затянется)

### 6. Документирование

Записывайте гипотезу и результаты:

**До теста:**
- Гипотеза: "Яркие превья увеличат CTR на 15%"
- Метрика: Конверсии (клики)

**После теста:**
- Результат: Вариант B увеличил конверсию на 16% (p=0.032)
- Решение: Внедрить вариант B на 100%
- Выводы: Яркость превья влияет на клики

### 7. Сегментация

Если возможно, анализируйте сегменты:

- Новые vs вернувшиеся пользователи
- Мобильные vs десктоп
- Разные регионы

Это может выявить скрытые паттерны.

## Типичные ошибки

### Ошибка 1: Слишком ранняя остановка

**Проблема**: Остановка теста после 100 конверсий.
**Результат**: Случайные результаты, p-value > 0.05.
**Решение**: Используйте калькулятор размера выборки или ждите p < 0.05.

### Ошибка 2: Игнорирование значимости

**Проблема**: "Вариант B лучше на 2%!", внедряем.
**Результат**: Разница случайна, никаких улучшений.
**Решение**: Проверяйте p-value и доверительные интервалы.

### Ошибка 3: Слишком много вариантов

**Проблема**: Тест с 8 вариантами по 12.5% трафика.
**Результат**: Тест длится месяц, недостаточно данных.
**Решение**: Начните с A/B теста (2 варианта).

### Ошибка 4: Тестирование без гипотезы

**Проблема**: "Просто попробуем разные варианты".
**Результат**: Неизвестно, что именно сработало.
**Решение**: Всегда формулируйте гипотезу заранее.

### Ошибка 5: Изменение теста во время работы

**Проблема**: Изменение распределения трафика на 3-й день.
**Результат**: Испорченные данные, невалидный тест.
**Решение**: Остановите тест и создайте новый.

## Калькулятор размера выборки

Минимальное количество конверсий для каждого варианта:

| Улучшение | Мин. конверсий на вариант | Мин. показов (при 10% baseline) |
|-----------|--------------------------|---------------------------------|
| 50% | 50 | 500 |
| 30% | 100 | 1,000 |
| 20% | 200 | 2,000 |
| 15% | 350 | 3,500 |
| 10% | 800 | 8,000 |
| 5% | 3,000 | 30,000 |

Пример: Если ожидаете улучшение на 15% и baseline конверсия 10%, нужно ~3,500 показов на вариант (7,000 всего для A/B теста).

## FAQ

### Сколько вариантов можно создать?

От 2 до 10. Рекомендуется 2-3 для быстрых результатов.

### Можно ли изменить тест после запуска?

Нет, тесты в статусе `running` нельзя изменять. Можно остановить и создать новый.

### Что такое p-value?

Вероятность получить такие же результаты случайно. p < 0.05 → значимый результат.

### Как долго должен длиться тест?

Зависит от трафика. Обычно 1-7 дней. Останавливайте когда p < 0.05.

### Можно ли удалять запущенные тесты?

Нет, сначала остановите тест (статус `stopped`), затем удалите.

### Что делать если тест незначимый (p > 0.05)?

Соберите больше данных или увеличьте длительность теста. Не принимайте решения.

### Как записываются метрики?

Через API эндпоинт `POST /api/ab-tests/metrics` или из сервиса `ABTestingService.record_metric()`.

### Можно ли автоматизировать остановку теста?

Да, используется Celery задача `stop_ab_test_task` для автоматической остановки по истечении `planned_duration_hours`.

## Примеры кода

### Создание теста (Python)

```python
from src.schemas.ab_testing import ABTestCreate, ABTestVariantCreate
from src.services.ab_testing_service import ABTestingService

test_data = ABTestCreate(
    name="Тест превью",
    description="Сравнение превью-изображений",
    hypothesis="Яркие превья увеличат конверсию",
    channel_id=uuid.uuid4(),
    planned_duration_hours=24,
    variants=[
        ABTestVariantCreate(
            name="Контроль",
            traffic_allocation=50,
            position=0,
            configuration={"thumbnail": "a.jpg"}
        ),
        ABTestVariantCreate(
            name="Вариант B",
            traffic_allocation=50,
            position=1,
            configuration={"thumbnail": "b.jpg"}
        )
    ]
)

test = await service.create_test(test_data)
```

### Запись метрики (TypeScript)

```typescript
import { recordABTestMetric } from '@/api/ab-testing';

// При клике по превью
async function handleThumbnailClick(variantId: string, userId: string) {
  await recordABTestMetric({
    variant_id: variantId,
    metric_type: 'clicks',
    metric_value: 1,
    metadata: { user_id: userId }
  });
}

// При подписке
async function handleSubscription(variantId: string, userId: string) {
  await recordABTestMetric({
    variant_id: variantId,
    metric_type: 'conversions',
    metric_value: 1,
    metadata: { user_id: userId }
  });
}
```

### Получение анализа (Python)

```python
from src.services.ab_testing_service import ABTestingService

analysis = await service.analyze_test(
    test_id=test_uuid,
    confidence_level=0.95
)

print(f"Победитель: {analysis.winner_variant_id}")
print(f"Статистически значимый: {analysis.is_significant}")
print(f"P-value: {analysis.p_value}")

for variant in analysis.variants:
    print(f"{variant.variant_name}: {variant.conversion_rate:.2%}")
    print(f"  CI: {variant.confidence_interval_lower:.2%} - {variant.confidence_interval_upper:.2%}")
```
